# Things to think about

Open questions where the project's direction depends on judgement more than on code. Any
answer, sketch or half-thought written here or brought to a session moves the work.

The questions are open on purpose. Where a few possibilities are named, they are examples to
start from, not a menu to choose between.

## The language (s on the 5-bit format)

1. **Programs as entries.** An s program is stored in the memory beside ordinary texts and
   has sums like any text. What, if anything, should its gematria mean, and what should the
   memory view show about a program?
2. **The first words of a project library.** s has std/core, line, text, gem, sh, logic and
   elec. Which words would a `std/anend.s` need first, so that an s program can do something
   interesting with the save: entries, lists, classifiers, scenes, blocks?
3. **Errors in a save.** When a program run from a block or a pipe fails, what should
   remain afterwards for someone to read and act on?

## Taxonomies and pipes

4. **What an answer carries.** A taxonomy node answers a question about a text. What should
   travel down the tree with that answer: the verdict, its confidence, the path so far,
   something else?
5. **How effects meet.** When several effects act on the same item, how should they combine,
   and where should the user see and change that?
6. **What flows through a pipe.** Texts, words, spans, placements and lists are all
   candidates. Which of these does the work need, and how do they relate when one pipe
   holds several?

## Scenes and the game

7. **What play is.** What would someone do in a scene for an hour and come away glad of it?
8. **Superflight writes by flying.** What should the order, speed and path of a flight
   mean for the text it produces?
9. **Texts in 3D.** Billboards, textures on blocks, and blocks made of a text's glyphs are
   some forms a text can take in a scene. What should each form say about the text?
10. **Logic and meaning in one machine.** Gates pass on signals. What would it mean for a gate
    to pass on texts, with classifiers as part of the logic?

## Classifiers as instruments

11. **Reading a weak classifier.** A classifier that scores poorly still tracks something.
    What would a view for reading what it latched onto show?
12. **A first taxonomy of one's own.** Which texts already gathered over the years would make
    the most telling first taxonomy, and what would its questions be?
13. **Tag sets beyond linguistics.** Which tag sets of one's own would show the idea best to
    someone new?

## The project as a whole

14. **The first five minutes.** What should a newcomer meet first so the idea lands?
15. **Fixed points.** Which parts of the project should never change, so everything else
    can change around them?
16. **A day with the app.** What does an ordinary day of use look like: what is opened
    first, typed, looked at, returned to?
